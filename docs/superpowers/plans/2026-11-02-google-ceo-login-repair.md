# Google CEO Login Repair Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `belcianycosmedionisio@gmail.com` the one and only CEO identity for Placurso Google sign-in, while preserving ordinary student login and the existing ANNAN engine.

**Architecture:** The `public.growth_ceo_identity` singleton is the sole source of the allowed CEO email and claimed Auth UUID. The Edge Function validates a confirmed Google Auth identity against that row; the browser always asks the server to classify a Google session and never authorizes CEO access from a hardcoded email. The existing static-site generation patch remains the source for login UI changes.

**Tech Stack:** Supabase Auth, Supabase Postgres migration, Supabase Edge Functions (Deno/TypeScript), static browser JavaScript generated by Python build scripts, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-02-google-ceo-login-repair-design.md`

## Global Constraints

- The only permitted CEO email is `belcianycosmedionisio@gmail.com`.
- A CEO session requires a valid JWT, confirmed email and Google provider metadata.
- The browser must not contain a CEO email allowlist or privileged database logic.
- Releasing the previous CEO mapping must not delete the old Auth user or any user data.
- The old Auth profile must be demoted from `admin` to `aluno`.
- `verify_jwt = true` must remain enabled for `annan-growth`.
- Never expose `SUPABASE_SERVICE_ROLE_KEY`, secret keys, or OAuth secrets to browser code.
- Keep the existing ANNAN engine and the ordinary student sign-in flow.

## Review Focus

- A verified Google login using the new CEO email must claim the singleton exactly once and be promoted to admin.
- The previous email must be rejected after the singleton is changed, even if its old Auth UUID remains valid.
- A non-Google provider or unconfirmed email must not claim CEO.
- A normal student Google login that receives CEO bootstrap `403` must continue through the student flow rather than showing a CEO error.
- A transient bootstrap/server failure must not silently grant admin access or falsely claim that the user is a student CEO.
